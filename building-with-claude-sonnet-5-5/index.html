Claude Sonnet 5.5 是 Opus 5.5 之后 Claude 5.5 家族的第二个模型。它相对 Sonnet 5 是明显升级：更聪明、更高效，快 30%。单 token 价格不变，而做同样的活 Sonnet 5.5 通常需要的 token 少得多，所以大多数工作的花费最多降 30%。

在 Sonnet 5.5 和 Opus 5.5 之间选

Claude 5.5 家族里，Opus 5.5 为需要仔细判断的复杂工作而造。Sonnet 5.5 用于范围明确的日常任务，比如修 bug、快速迭代功能。它还能做出精致的文档、幻灯片和表格，设计眼光强。它的速度让它适合快速迭代。Claude Haiku 5.5 未来几周会加入家族，面向高吞吐、低延迟的工作流。

你的负载 先用 范围明确的日常编码：修 bug、快速迭代功能、对照需求验证 Sonnet 5.5 高吞吐的日常开发 Sonnet 5.5 精致的文档、幻灯片和表格，比如一页纸、图表、总结页、文档编辑和表格整理，设计眼光是加分项 Sonnet 5.5 你反复跑的、定义明确的 agent 任务：调查、审阅、起草 Sonnet 5.5 需要仔细判断的复杂工作，包括长程 agentic 编码和知识工作 Opus 5.5 最难的问题，需要最聪明的模型 Opus 5.5

"在 Epic 的早期测试里，Claude Sonnet 5.5 达到了你预期更高级别模型的质量线，扛住了系统设计审计和数据流评审。新模型管理了游戏系统架构的数万行代码，保持响应利落，处理数小时的任务，并且用了更少规定性的 prompting。"（Daniel Vogel，Epic Games COO）

任务有明确规格、有办法检查结果时，Sonnet 5.5 最合适。用prompting 指南的话说："最难、程最远的活，Opus 模型是更好的选择。"

价格

每百万 token Sonnet 5.5 Opus 5.5 输入 $2 $4 输出 $10 $20 缓存写入，5 分钟 $2.50 $5 缓存写入，1 小时 $4 $8 缓存读取 $0.20 $0.20

Sonnet 5.5 的所有价格，包括 batch 处理和 prompt caching，都和 Sonnet 5 一样，所以换 model ID 不会改变你的单 token 账单。仅美国推理（inference_geo: "us"）是标准价的 1.1 倍。

单 token 价格虽然不变，总账单会变：前面说过，Sonnet 5.5 每个任务通常比 Sonnet 5 用更少的 token。

注意各个 surface 对 Sonnet 的默认 effort 可以不同，比如 Claude Platform 上是 high，Claude Code 里是 medium。

Sonnet 5.5 用高分辨率图像档，长边最高 2576 像素，一张 2000×1500 的图大约费 Sonnet 4.6、Sonnet 4.5 或 Haiku 4.5 的 2.5 倍 token。不需要那个细节的话，发送前先缩小。

模型细节

项目 Sonnet 5.5 Model ID Claude API、AWS 上的 Claude Platform、Google Cloud 和 Microsoft Foundry 上是 claude-sonnet-5-5；Amazon Bedrock 上是 anthropic.claude-sonnet-5-5 上下文窗口 1M token，原生，无需 beta header 最大输出 128k token；Message Batches API 上用 output-300k-2026-03-24 beta header 可到 300k 知识截止 2026 年 6 月 思考 默认开启（adaptive thinking）；between_tools 关闭前置思考 Effort 档 low、medium、high、xhigh、max 默认 effort Claude API 上 high；Claude Code 里 medium Tokenizer 与 Sonnet 5 相同 最小可缓存 prompt 512 token（Sonnet 5 是 1,024） 限流 与 Sonnet 5 独立，默认档数值相同 Priority Tier Claude API 可用 数据保留 符合条件的客户可用 zero data retention

Claude API 默认 high，让你从强结果起步。从那里开始，评估，再选你的负载需要的 effort 档。动 xhigh 或 max 的念头时，记住 Sonnet 5.5 会想得更久、花得更多。某些任务上，你会丢掉让 Sonnet 有用的东西：质量、速度和成本的平衡。那种情况，考虑 Opus 5.5。

从 Sonnet 5 迁移

思考默认开启。如果你之前跑 Sonnet 5 时关了思考，可以用 between_tools 关掉前置思考。下面第 1 步演示怎么做。

把 model ID 改成 claude-sonnet-5-5，然后过五个破坏性变更和一个响应形状变更。Sonnet 5.5 迁移指南把每个都讲全了。

Claude Code 也能替你迁移。跑 /claude-api migrate this project to claude-sonnet-5-5 调用内置的 Claude API skill，它会把 model ID 替换和破坏性参数变更应用到整个代码库。

1. 用 between_tools 关闭前置思考

Sonnet 5.5 上，没有 thinking 字段的请求按 adaptive thinking 跑，thinking: {"type": "disabled"} 返回 400 错误。改发新的 between_tools 设置。用 between_tools 时思考只发生在工具调用之间，总响应时间不变或更快。

例子还把 effort 从 xhigh 降到 high，因为 between_tools 有这些限制：

  • between_tools 支持 low、medium 和 high effort。xhigh 或 max 返回 400 错误；要在那两档跑，用 adaptive thinking。
  • 它不接受其他字段。一起发 display、budget_tokens 或 block_binding 返回 400 错误。
  • 用 between_tools 时，effort 不能对话中途变。想每个回合不同 effort，用 adaptive thinking。
  • 模型在工具调用之间写的短进度更新仍以 thinking block 返回，带摘要文本。按类型读 content block，这些 block 原样和 assistant 回合其余部分一起传回。没有工具时，响应只有文本。
  • 所有提供 Sonnet 5.5 的平台都支持，无需 beta header。你的 SDK 版本没定义 between_tools 的话，升级。

    • 用 between_tools 关掉前置思考后，没有工具、需要几步推导的请求改用 adaptive thinking。

    2. 用 auto 加 strict tools 替换强制 tool_choice

    类型为 any 或 tool 的 tool_choice 返回 400 错误，token counting 端点也一样。发 auto，把工具标成 strict: true 让输入符合 schema，并在 prompt 里说什么时候用它：

    strict tool use 要求每个对象上都有 additionalProperties: false。

    3. 对话保持只追加

    Sonnet 5.5 的 thinking block 绑在模型和对话上。Sonnet 5.5 读得懂 Sonnet 5 的 thinking block，所以从 Sonnet 5 切到 Sonnet 5.5 的对话保留它的推理。其他模型读不了 Sonnet 5.5 的 block。

    4. computer use 挪到 toolset

    Claude API 和 Google Cloud 上，Sonnet 5.5 只通过 {"type": "computer_toolset_20260801"} 支持 computer use；声明 computer_20251124 的请求返回 400 错误。请求里去掉 anthropic-beta: computer-use-2025-11-24 header，SDK 里去掉 betas 参数，通过标准客户端而不是 beta 命名空间调 Messages API。替换 tools 条目，agent 循环按成员 tool_use block、批量动作和结果上的 toolset_name 更新。如果还发 fine-grained-tool-streaming-2025-05-14 beta header，也去掉，因为它和 toolset 条目一起出现会返回 400 错误；改在需要它的每个工具上设 eager_input_streaming: true。Amazon Bedrock 仍接受 computer_20251124。

    5. 检查 advisor 配对

    用 advisor tool 时，Sonnet 5.5 executor 拒绝 Opus 4.8、Opus 4.7 和 Sonnet 5 当 advisor。可用的 advisor 包括 Opus 5.5、Opus 5 和 Sonnet 5.5 本身。每个可用 advisor 的建议都加密返回，以 advisor_redacted_result block 形式，你的代码读不到建议文本。

    6. 从 thinking block 读工具调用之间的文本

    这个变更不产生错误，但 UI 可能不再显示模型在工具调用之间写的笔记。那些笔记超过一两句时，以进度更新 thinking block 返回，默认 display 下它们是空的。

    用 adaptive thinking 时，把 thinking.display 设为 "updates"（beta，带 thinking-display-updates-2026-08-18 header）或 "summarized"，把每个非空 thinking block 渲染在它后面 tool_use block 之前。用 between_tools 时，文本直接返回，不用 display。

    Sonnet 5.5 还加了按消息的 effort（beta）、对话中途的 system 消息和对话中途的工具变更（beta）。如果你从 Sonnet 4.6 或更早、或从 Haiku 4.5 迁移，迁移指南有每个起始模型的清单。

    调优

    重跑你的 effort 扫描

    Effort 档重新校准过，同一档产生的思考量与 Sonnet 5 上不同，旧设置不能照搬。除非负载是 agentic 或对延迟敏感，从 high 开始。agentic 编码和多步工具使用：规格明确的从 medium 开始，更难或更长的升到 high。聊天和其他对延迟敏感的活：从 medium 或 low 开始。xhigh 或 max 只在你的 evals 显示出质量增益的地方用。

    思考计入 max_tokens，留出余量。agentic 编码把 max_tokens 设成 128,000，模型的顶格，并流式读响应。想让思考少一点，降 effort 档——在 system prompt 里要求模型少想，并不可靠地减少它。

    移除 Sonnet 5 的绕行手段

    现成的 Sonnet 5 prompt 不改也表现良好。如果你的 prompt 带着绕行手段，比如拒绝转向、tool call 重试垫片或 "do not be lazy"，删掉它们，先重跑 evals，再谈其他调优。

    low effort 下要真实检查

    Sonnet 5.5 报改动完成前一般会自己验证，但在 low effort 下有时跳过真正跑改动的那道检查。看到没有测试或构建输出就报完成的改动，prompting 指南推荐这段 system prompt：

    用 thinking.display 展示进度

    别要求模型在响应里写出推理过程，那会招来 reasoning_extraction 拒绝。改读 summarized thinking：

    要单独的面向用户的进度说明，用 display: "updates"（beta）。想要可预期的点上给更新——比如第一次工具调用前一行、结尾一句小结——在 system prompt 里说。

    多缓存你的 prompt

    最小可缓存 prompt 降到 512 token，更短的 system prompt 和工具定义现在有资格了。缓存读取是输入价的十分之一。请求之间改顶层 effort 会使缓存失效；只想让一个回合跑不同档，用 per-message effort（beta），它保住缓存。

    拒绝与兜底

    我们的自动化行为审计里，Sonnet 5.5 在大多数对齐和诚实度指标上优于或持平 Sonnet 5。它也是第一个带与最强模型相近的网络安全防护的 Sonnet 模型。大多数常规软件开发不受影响。

    被拒的请求返回 HTTP 200，stop_reason: "refusal"，stop_details 指明五个类别之一：cyber、bio、frontier_llm、reasoning_extraction 或 general_harms。服务端兜底（fallbacks: "default"，beta，Claude API）把 cyber 和 frontier_llm 的拒绝在 Sonnet 5 上重试，其余三个不重试。也可以用 SDK middleware 或自己的重试。

    正当的安全工作，Cyber Verification Program 很快会把 Sonnet 5.5 纳入。

    可用性

    Claude Sonnet 5.5 今天起在以下平台可用。开发者平台上用这些 model ID：

  • Claude API，claude-sonnet-5-5
  • Amazon Bedrock，anthropic.claude-sonnet-5-5
  • AWS 上的 Claude Platform，claude-sonnet-5-5
  • Google Cloud，claude-sonnet-5-5
  • Microsoft Foundry，claude-sonnet-5-5，仅 Global Standard 部署

    • 在 Claude Code 里

    从 Claude Code v2.1.284（TypeScript Agent SDK v0.3.284 或更新）起，sonnet 别名在 Claude API 上解析到 Sonnet 5.5。默认 medium effort 运行，1M 上下文窗口原生。Claude Code 里 Sonnet 5.5 不能关思考，effort 决定模型想多少。Sonnet 5.5 没有 fast mode。default 模型仍是 Opus 5.5，范围明确的任务用 /model sonnet 切换。

    希望你用得开心，反馈照旧随便给。

    import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=4096,
    messages=[
        {
            "role": "user",
            "content": "Analyze the trade-offs between microservices and monolithic architectures",
        }
    ],
    output_config={"effort": "medium"},
)

for block in response.content:
    if block.type == "text":
        print(block.text)
    # Before: Claude Sonnet 5
client.messages.create(

    max_tokens=16000,

)

# After: Claude Sonnet 5.5
