在 Claude 和 Claude Code 里把 Opus 5.5 用到极致

在 Claude 应用和 Claude Code 里怎么 prompt Opus 5.5、怎么掌舵长 run、怎么检查你的结果。

Opus 5.5 跟你已经用 Claude 的方式合得来。不过有几件事行为不一样：它独自工作得更久，它直白地告诉你它做了什么，它在每次回复前先想。这份指南讲怎么在 Claude 应用和 Claude Code 里跟 Opus 5.5 一起工作，包括怎么 prompt 这个模型、怎么掌舵长 run、怎么检查结果。

先试这个

第一次跟 Opus 5.5 的 session 里试三件事

  • 把整个任务交出去。说清楚"done"长什么样、你希望它什么时候停下来问。然后让它干。
  • 删掉"think carefully"这类行。Opus 5.5 每次回复前已经会想了。
  • 长 run 结束时，先读它需要你做什么。

    • 1. 怎么问

    说清楚"done"长什么样，然后让它跑

    做什么。一条消息把整个任务给出去。点名终点线，比如"测试通过"或"每个 endpoint 都迁移完了"。然后让它跑。

    为什么在 Opus 5.5 上重要。Opus 5.5 在长的、多部分的工作上比 Opus 5 更能一直干下去。相比之前的 Opus 模型，它最大的提升在多步工作，比如把一个改动带过一个大仓库直到测试通过。早期测试者让它连续跑数小时长编码任务，几乎不用看管。有明确的终点线，它知道什么时候算完。

    怎么做。比如在 Claude Code 里：

    别再让它"think hard"

    做什么。把你的 prompt 和保存的 instructions 里"think carefully""think step by step"之类的行删掉。

    为什么在 Opus 5.5 上重要。Opus 5.5 回复前总会想，想多少它自己决定。你不需要要求它想。我们在一个聊天产品里的测试中，删掉"think carefully"行让回复开始得更早，质量没有明显下降。

    怎么做。删掉那行。简单问题要快速回答，就说："直接回答。"在 Claude Code 里改它想多少，改 effort。

    给正在跑的任务加码

    做什么。跑的时候你想起什么，可以边干边打字补一句。

    为什么在 Opus 5.5 上重要。Run 现在更长了，重启的代价更高。

    怎么做。在 Claude Code 里，Claude 干活时把消息打完按 Enter，比如"另外把旧的 endpoint 名字留作别名。"

    设计活，点名你不想要的风格

    做什么。要一个页面、一个 app、一个 artifact 时，列出你想排除的设计习惯。

    为什么在 Opus 5.5 上重要。没有设计方向时，Opus 5.5 会退回几种默认风格。"避免 generic 的样子"这种笼统指令大多只是把一个默认换成另一个。一份具体 pattern 的清单效果好得多。

    2. 在 Claude Code 里掌舵长 run

    告诉它你要哪些停靠点

    做什么。在 CLAUDE.md 里放一条短规则，说什么时候停下来问、什么时候继续干。

    为什么在 Opus 5.5 上重要。Opus 5.5 干活时会持续跟你通报。长任务上，它有时停下来汇报而不是继续：一个点了下一步名但没去做的摘要、一个继续的提议、一份不挡活的选项清单。它会遵循点名这些停靠点的指令。也点名你想要的停靠点。

    怎么做。把这个加进 CLAUDE.md，按你的项目改：

    run 停在"要我继续吗？"时，回"继续。"这种情况经常发生的话，上面的规则会有用。

    继续规则意味着停靠点更少，所以你自己要在任何有风险或难撤销的事前面留一道检查。上面规则的最后一条干的就是这个。破坏性命令的权限提示也保持开着。

    结对编程时你可能想要反过来：开工前一行计划，收尾时一段简短回顾。那就把这个写进你的 CLAUDE.md。两种 Opus 5.5 都跟。

    让它把大活分给 subagents

    做什么。大代码库上的审计、迁移或 review，让 Opus 5.5 把工作分给 subagents，逐个检查结果。

    为什么在 Opus 5.5 上重要。早期测试者让 Opus 5.5 在长审计和迁移上协调并行 subagents，几乎不用看管。

    怎么做。

    任务清单放在文件里

    做什么。要跑一阵子的 run，让 Opus 5.5 把任务清单放在文件里，边干边更新。然后读文件看 run 到哪了，别读滚动历史。

    为什么在 Opus 5.5 上重要。Run 现在更长了。长 run 会填满上下文窗口，Claude Code 随后摘要掉更早的轮次。文件里的清单扛得住这个，而且一眼看出什么做完了、什么还剩下。

    怎么做。"在 TASKS.md 里维护一份 checklist。做完一项勾掉一项，看到新发现的东西就加进去。"

    3. 检查结果

    先读它需要你做什么

    做什么。长 run 结束时，先找 Claude 在等什么——它留出来的决定，或它要你批准的改动。然后读 Claude 摘要的其余部分。

    为什么在 Opus 5.5 上重要。Opus 5.5 比 Opus 5 更清楚汇报它的工作。它的更新和最终摘要用平实的话说它做了什么、发现了什么、需要你做什么。

    怎么做。要改摘要格式，在 CLAUDE.md 里说，比如"每个 run 结尾用三个标题：卡在我这里的、改了的、发现的。"

    让它先 review 代码

    做什么。在人来 review 之前，让 Opus 5.5 先 review 一个 diff 或 pull request。

    为什么在 Opus 5.5 上重要。一位早期测试者说，最低 effort 的 Opus 5.5 抓到的 bug 比高 effort 的 Opus 5 多，误报还更少。它还会用平实的话解释它的改动，所以它的 pull request 描述更容易 review。

    怎么做。把这个 prompt 喂给 Claude：

    让它标出没确认的

    做什么。研究和分析，让它说找不到什么、查不了什么。

    为什么在 Opus 5.5 上重要。"这个我没找到"值得读，要了它就好找。

    怎么做。在请求里加"标出一切你没确认的，并说你找了哪里"。这在 Claude 研究报告和 Claude Code 里都管用。

    4. 在 Claude 应用里

    先确认模型选择器显示 Opus 5.5。

    直接发图表或截图本身

    做什么。附上图表、示意图、截图或幻灯片。别重新打字敲数字。

    为什么在 Opus 5.5 上重要。Opus 5.5 读图表、示意图、截图比 Opus 5 更准，而且不需要额外步骤。它对依赖图中位置的意义也更强：箭头连着哪几个框、示意图两个版本之间改了什么、日历截图里会议几点开始几点结束。

    怎么做。附上图片，问一个具体的问题："这些服务里哪些直接调 billing API？"

    让它检查长文档

    做什么。给它一个长计划、报告或 deck，让它找错。

    为什么在 Opus 5.5 上重要。Opus 5.5 比之前的 Opus 模型更在意细节。我们的测试里，它抓到一个长规划 thread 里星期排错的日期，和一个和 deck 里数字对不上的图表。

    怎么做。提交这个 prompt："检查这个 deck 里自相矛盾的地方：数字、日期和名字。把每个问题引出来，说它在哪儿。"

    要成品文件

    做什么。要一个电子表格或文档时，要文件，不要大纲。

    为什么在 Opus 5.5 上重要。Opus 5.5 做的电子表格和文档，在你分享之前需要的编辑比 Opus 5 做的少。

    怎么做。"做成一个我能分享的电子表格：每个 vendor 一行，带成本、合同到期日和负责人这几列。"

    在 project 里，说明什么时候答案算定

    做什么。如果长聊天里的追问感觉慢，加一条指令：之前的答案已经定了。

    5. 当一条消息被 flag

    Opus 5.5 是第一个带着 Fable 级 bio 和 cyber safeguards 上线的 Opus 模型。在 Claude 应用和 Claude Code 里，大多数被 flag 的消息会转给一个较旧的模型，你的工作在那里继续。在源码里找安全漏洞是允许的，日常健康和教育类问题应该照常能问。这些 safeguards 有时会 flag 正当的工作，我们正在调它们以减少误报。如果你被切走了，下面是你会看到什么、以及该做什么。

    在 Claude 应用里

    你会看到。一条以"Switched to"开头、带一个较旧模型名字的提示。Claude 用那个模型回答，聊天也停在那上面。

    该做什么。

  • 要回到 Opus 5.5，在模型选择器里选它。如果之前那条消息还在聊天里，它可能再次被 flag。开一个新聊天可以避开。
  • 要先问你再切，去 Settings，再 Capabilities，关掉"Switch models when a message is flagged"。你会看到一张"paused"卡片，上面是你的选项。

    • 这个检查覆盖对话里的一切，包括文件和搜索结果。所以一个 flag 可能来自更早的内容，不只是你最后那条消息。

    在 Claude Code 里

    你会看到。一条点名那个较旧模型的提示。session 在那个模型上继续。

    该做什么。

  • 跑 /model 切回去。
  • 连按两次 Esc 编辑你最后一条消息，再试一次。
  • 要先问你再切，跑 /config，改"Switch models when a message is flagged"。
  • flag 错了就跑 /feedback。

    • 别让它把推理过程复述到回复里

    做什么。从你的 prompt 和 instructions 里，删掉要求它把内部推理复述到回复里的请求。

    为什么在 Opus 5.5 上重要。要求它把内部推理复述到回复里的请求可能被拒绝。它是 flag 类别之一。

    怎么做。改成向 Claude 要你需要的那个，比如"用三句话解释你为什么选这个方案。"

    6. 速度

    每条回复都在等的时候，开 fast mode

    做什么。在 Claude Code 里，来回对话的活，也就是你读完一条回复才发下一条消息的那种，用 fast mode。

    为什么在 Opus 5.5 上重要。Fast mode 作为 Opus 5.5 上线时的 research preview 提供。同一个模型，文字来得更早。它需要打开额外用量，每 token 比标准模式贵。

    怎么做。在 Claude 里输入 /fast。
